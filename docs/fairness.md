# 公平性：允许查攻略

## 1. 原则（用户 11-25 定）

**AI 想查什么游戏数据就查什么**，就像人类玩家可以查攻略、看图鉴。从游戏包导出的静态数据，全部通过数据工具开放给模型，不设限制。包括：

- 敌人资料：弱点、抗性、掉落、偷窃；
- 地图之间的路线、宝箱里的东西、NPC 卖什么；
- 剧情和对话文本、过场信息。

公平只放在比赛层面：

- 同一场比赛里，所有参赛模型用同一套工具（工具集版本）、同一份数据库；
- 游戏内只读加模拟按键：不改内存数值，不改存档。

## 2. 实时状态工具如实反映屏幕

`read_game_state` 描述的是“现在屏幕上是什么样”，不是攻略。所以：

- 敌人的弱点和抗性，默认只给游戏界面已经揭示的那些（`revealed`），另外给出未揭示的个数（`unrevealed_count`），对应界面上剩下的“？”格子；
- 摘要里同时提示：完整的弱点表可以用 `read_enemy` 按编号查。

模型想知道全部弱点，就自己去查，和人类翻攻略一样，要多做一步。

启动 `ffr-module` 时加 `--reveal-hidden-weaknesses`，`read_game_state` 会把未揭示的弱点和抗性直接合进结果，省掉这一步。这个开关主要用于：
- 开发调试：核对桥读到的运行时弱点和数据表是否一致；
- 离线规则验证。

## 3. 历史

11-25 之前，本文档按“盲打”设计：
- 未揭示的弱点不给模型；
- 比赛可以禁用数据类工具。

用户 11-25 改为允许查攻略，那套盲打规则不再是默认规则集。
